Coding Rules
    Architectural Separation: Maintain strict separation between the shared/, app/, and daemon/ directories. Target a maximum of 150 lines per file whenever possible.
    Async Programming: Use tokio for all I/O, ASR (Speech Recognition), and LLM tasks. Exception: PipeWire audio capture requires a dedicated sync thread.
    IPC (Inter-Process Communication): Use Unix Domain Sockets with a 4-byte big-endian length prefix and UTF-8 payload. Verify ucred (PID/UID) to ensure security.
    Display System: Wayland-first via the XDG GlobalShortcuts portal. X11 fallback via XGrabKey is permitted but must be strictly isolated using conditional compilation.
    Error Handling: The use of .unwrap(), .expect(), or panic!() is strictly forbidden. Use the thiserror crate for module-level errors and return clear, descriptive errors.
    Zero Persistence: Audio data and transcripts must remain in RAM only. No disk writes, no /tmp usage, and absolutely no telemetry collection. This is the core foundation of privacy.
    Memory Safety: You must apply Zeroize to all API keys and transcript buffers immediately after use — this is mandatory.
    Data Injection: Manipulation of /dev/uinput must be handled exclusively via the daemon process. Synchronize keyboard events to prevent character interleaving.
    Comments: Never reference task names, numbers, or issue numbers in code comments or variable names. The code must be clean and self-documenting.
    OpenRouter: Before writing any code that interacts with the OpenRouter API, fetch and read the official documentation to ensure you are up to date on models and parameters.
    Code Quality: Write for extensibility — use clean abstractions, adhere to the single responsibility principle, and never take shortcuts that introduce technical debt.
    Pipeline Latency: The time elapsed from releasing the shortcut key to typing the first character is a critical product feature. Speed is paramount.
    Wizard Navigation: Every wizard page function must accept (state: Rc<RefCell<WizardState>>, nav: &Navigator) to ensure testable state management that is completely decoupled from the UI.
